Actor attribution for ASTRA decisions

ASTRA records what was decided in a scientific analysis — which options were considered, chosen, or excluded, and why. It does not record who was involved. In today's records, a choice a researcher examined and rejected is indistinguishable from a default nobody looked at.

Who proposed this option?
Who ruled it out?
Who signed off?

RFC-0004 adds a small, optional, fully additive actor layer: a registry of the humans and agents on an analysis, plus attribution fields exactly where a “who” is meaningful. This page walks one real, recorded decision from a dissertation pipeline — every number and every error message below is a captured output of the committed code and validator.

The role vocabulary — a CRediT subset plus flagged extensions

Seven roles are CRediT (Contributor Roles Taxonomy) terms scoped down to a single decision or selection; three are extensions naming agent work CRediT has no term for. Two are human-owned.

rolehumanagentmarks
conceptualization human-only✓—frames the decision
methodology✓✓proposes an option or designs the method
data_curation✓✓selects or vouches for the data
software✓✓writes or maintains the recipe code
formal_analysis✓✓runs the analysis, computes the result
validation✓✓checks, rules out an option, catches an error
supervision human-only✓—oversight and final sign-off
planner extension✓✓decomposes and sequences the work
executor extension✓✓runs code or tools, returns results
researcher extension✓✓retrieves prior work, assembles context

In the demo below: the agent held methodology (it proposed Mahalanobis), the human held validation (they ruled it out). The two human-owned roles are exactly the accountability boundary — a human frames the decision and signs off.

New pieces, by name

classes
  • Actor — one flat class, type-keyed rules (no subclasses)
  • Attribution — {actor, role}; shorthand: bare actor id
  • ResearcherId — scholarly ids, at least one required if present
enums
  • ActorType — human | agent
  • HumanRole — all 10 roles
  • AgentRole — HumanRole minus the 2 human-only terms
slots
  • actors: — new optional analysis-level registry
  • Option: proposed_by, excluded_by (attribution) + excluded_at, exclusion_rationale (exclusion record: date, text)
  • Selection: selected_by, reviewed_by (attribution)

Everything is optional and additive: an analysis with no actors: key, and a universe using the scalar shorthand, validate exactly as before — byte for byte.

demo · scene 1 · the trap

Ask the assistant a pure theory question

Sentences are points in an 18-dimensional embedding space. The topic groups they belong to are stretched, not round. Which distance is the better test of whether a sentence belongs to a group — Euclidean or Mahalanobis?

claude_code · agent · claude-opus-4-8 TRACE trace_20260509_305aaf · 2026-05-09

Mahalanobis. It adapts to each group's stretched shape — distances shrink along directions the group naturally varies in and grow along directions it doesn't. Euclidean treats every direction alike, so it ignores the very structure the clusters have.

Correct on paper. It is what the study team assumed too — the pipeline was built with Mahalanobis as the working choice.

Corpus-wide, same story: Euclidean kept 1,143 of 1,662 sentences (68.8%); Mahalanobis kept 846 (50.9%) — and 0 of 2 on the Climate Adaptation topic. The covariance behind the “shape-aware” metric is estimated from a handful of reference sentences in 18 dimensions: the shape it adapts to is mostly estimation noise. Settling that took a person reading the sentences — and that judgment is what is worth recording.

demo · scene 3 · enforcement

Excluded means excluded — and attribution is checked, not decorative

The study excluded Mahalanobis on 2026-06-11. ASTRA's validator makes that exclusion structural: no universe may quietly re-select a ruled-out option, and every attribution field is cross-checked against the actor registry.

bad-universe.yaml — try to bring the excluded option back
id: bad_universe
decisions:
  distance_metric: mahalanobis   # ← excluded on 2026-06-11
✓ Schema validation passed

Semantic validation errors:
  • [EXCLUDED_OPTION_SELECTED] decisions.distance_metric: Universe selects
    excluded option 'mahalanobis' for decision 'distance_metric'
exit status 1

A ruled-out option cannot come back as a real choice. The scene-2 replay ran through explicit decision values — a diagnostic, never a universe.

demo · scene 4 · the actor layer

The whole layer is an additive diff

The plain file already says what happened — Mahalanobis excluded, with the full technical reason. It cannot say who. Adding RFC-0004 changes nothing that exists: it only adds.

analysis/plain/astra.yaml → analysis/astra.yaml 
id: korean_pledges_actor_demo
# … inputs, outputs unchanged …
actors:
  oliver:
    type: human
  claude_code:
    type: agent
    model: claude-opus-4-8     # required for agents
    harness: claude-code
    version: "2026-05"
decisions:
  distance_metric:
    default: euclidean
    options:
      euclidean:   # … unchanged …
      mahalanobis:
        excluded: true
        excluded_reason: Retains 68/218 (31.2%) vs 161/218 (73.9%)…
        proposed_by: {actor: claude_code, role: methodology}
        excluded_by: {actor: oliver, role: validation}
        excluded_at: "2026-06-11"
        exclusion_rationale: >-
          The assumed-best option, excluded after inspection: theoretically
          superior shape adaptation, but retention was implausibly low and
          reviewing the retained sentences showed the simple metric was
          producing the better set. Theory needed a human override.
the layer = 16 added YAML lines · nothing removed, nothing rewritten (the committed twins additionally differ only in comments) — every existing astra.yaml and universe file stays valid, byte for byte. Roles come from a CRediT-derived vocabulary; conceptualization and supervision are human-only.

The closing line

The assistant proposed the method that is better on paper — the same answer it gives live in scene 1. A person read the results and overruled it. Without this layer the file only says Mahalanobis was ruled out. With it, the file says who proposed it, who overruled it, and when — the exact record that accountability, credit, and oversight of AI-assisted science need.
